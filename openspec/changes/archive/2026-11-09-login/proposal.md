# Proposal

## Why

Приложением хотят пользоваться друзья, а сейчас любой, кто откроет адрес, видит и меняет одни и те же контакты. Поэтому на сервере до сих пор только тестовые данные. Нужен вход по почте: каждый ведёт свои контакты и не видит чужие. Требования владельца — `specs/02-пользователи-вход.md`.

## What Changes

- Без входа приложение не открывается: любая страница ведёт на страницу входа — поле почты и кнопка «Получить ссылку»
- Вход только по ссылке из письма, паролей нет. Первый вход и есть регистрация, имя не спрашиваем
- Ссылка работает один раз и 15 минут; новая ссылка отменяет прежние; не больше 3 писем на одну почту за 10 минут
- Вход держится 30 дней с последнего захода на устройстве, можно сидеть с нескольких устройств сразу. В шапке — почта и кнопка «Выйти»; выход только на этом устройстве
- Письмо «Вход в Личную CRM» от «Личная CRM» с кнопкой «Войти». На компьютере и в автотестах письма попадают в почтовый ящик-заглушку Mailpit, на сервере уходят по-настоящему через Resend. Куда слать, решают настройки, а не код
- У каждого контакта и каждой группы появляется владелец. Список, поиск, карточка, заметки, группы, фильтр и «Пора связаться» показывают только свои данные. Чужой контакт по прямой ссылке — «Контакт не найден». Права проверяет сервер в каждом запросе
- **BREAKING** Название группы теперь не повторяется только среди групп одного человека: у A и у B может быть по группе «Друзья»
- Новый пользователь видит пустой список и подсказку «Добавьте первый контакт»
- Все контакты, заметки и группы, которые уже есть в базе, достаются владельцу — пользователю с моей почтой. Демо-данные тоже создаются у него. Ни одна запись не теряется
- **BREAKING** Откатить эту выкатку можно только целиком: база из бэкапа, снятого перед выкаткой, и прошлая версия приложения. Всё, что друзья внесут после выкатки, при таком откате пропадёт

## Capabilities

### New Capabilities

- `user-auth`: вход по ссылке из письма, письмо со ссылкой, сколько держится вход, выход, почта в шапке, куда уходят письма
- `data-ownership`: у данных есть владелец: каждый видит и меняет только своё, чужое не открывается ни в интерфейсе, ни прямым запросом; данные, которые были до входа, достаются владельцу

### Modified Capabilities

- `contact-groups`: требование «Название группы» — название не повторяется среди групп одного пользователя, а не всего приложения

## Impact

- База: таблицы Better Auth для пользователей, сеансов и ссылок входа, своя таблица `login_links` для лимита писем; в `contacts` и `groups` новое поле `owner_id`. Миграция меняет существующие данные (проставляет им владельца), поэтому покажу её до merge
- Код: страница входа и страница устаревшей ссылки, шапка, проверка входа на всех страницах и во всех действиях, запросы к базе с владельцем (`src/db/queries.ts`, `src/app/actions.ts`), заполнение базы демо-данными (`scripts/seed.ts`), применение миграций (`scripts/migrate.ts`)
- Новые библиотеки: `better-auth` и `nodemailer` (их требует спека 02 и стек в `CLAUDE.md`), `@types/nodemailer` для типов. Новые сервисы: Mailpit в Docker (на компьютере и в CI), Resend на сервере
- Настройки: новые строки в `.env` на компьютере и на сервере и в `.env.example`. Файлы `.env` я не трогаю — скажу, какие строки добавить
- Docker и выкатка: Mailpit в `docker-compose.yml`; новые настройки в `deploy/compose.yaml`; Mailpit и тесты базы в CI
- Тесты: все существующие e2e-тесты сначала входят под пользователем; новые e2e-тесты входа и разделения данных; тесты на настоящей базе, что чужое не читается и не меняется
- `README.md`: вход, Mailpit, новые настройки, порядок отката этой выкатки
- Только владелец: аккаунт Resend, подтверждение домена (записи DNS в reg.ru), ключ Resend и остальные строки в `.env` на сервере
- `specs/01-продуктовая-идея.md` не меняем, хотя «Вход и регистрация» там в списке «Не делать»: так решил владелец

## Решения владельца по вопросам при планировании

- Почта владельца, которой достаются уже существующие данные и демо-данные, берётся из строки `OWNER_EMAIL` в `.env` на компьютере и на сервере. В коде почты нет: репозиторий на GitHub публичный
- Письма уходят с адреса `noreply@mail.crm.context-crm.site`, как в спеке
- Все новые тексты — на «вы», как остальное приложение: «Проверьте адрес почты», «Ссылка устарела, запросите новую», «Слишком часто, попробуйте через несколько минут», «Добавьте первый контакт». В `specs/02-пользователи-вход.md` они остались на «ты»; верными считаются тексты на «вы» из требований этого изменения
- `specs/01-продуктовая-идея.md` остаётся как есть

## Решения, принятые за владельца

Этого нет в спеке, поправьте, если не так:

- Страница входа: заголовок «Вход», поле «Почта», кнопка «Получить ссылку». Уже вошедший, открыв страницу входа, попадает на список контактов
- После отправки форма остаётся на месте, под кнопкой «Ссылка для входа отправлена на <почта>». Нажал кнопку ещё раз — пришла новая ссылка, прежняя перестала работать
- Ошибки «Проверьте адрес почты» и «Слишком часто, попробуйте через несколько минут» — под полем почты
- Письмо не ушло, потому что почтовый сервис не ответил: под полем «Не удалось отправить письмо, попробуйте ещё раз». В лимит 3 писем такая попытка не идёт
- На странице устаревшей ссылки кнопка называется «На страницу входа»
- Несуществующий контакт по прямой ссылке тоже показывает «Контакт не найден», а не общее «Такой страницы нет». Иначе по разнице сообщений можно было бы понять, что за номером скрыт чужой контакт
- Подсказка «Добавьте первый контакт» заменяет нынешнюю «Добавьте первого человека — нажмите «Добавить контакт»». Заголовок «Пока нет ни одного контакта» остаётся
- Открыл ссылку из письма, когда уже вошёл под другой почтой, — теперь внутри под почтой из ссылки
- 30 дней «с последнего захода» продлеваются не чаще раза в сутки, то есть с точностью до дня
- Адрес `/health` открыт без входа: по нему проверяется выкатка, данных он не отдаёт
- Если строки `OWNER_EMAIL` нет, а в базе уже есть данные, выкатка останавливается на миграциях: база не меняется, работает прежняя версия
