# Design

## Context

Главная (`src/app/page.tsx`) — серверный компонент с `dynamic = "force-dynamic"`. Он читает весь список одним запросом `listContacts(ownerId, query, groupIds)` (`src/db/queries.ts`), группирует его по буквам и рисует в окне «контакты.exe». Счётчик «Найдено: N из M» берёт N из длины этого списка, M — из `countContacts(ownerId)`.

Состояние списка уже живёт в адресе: `q` — поиск, `group` (повторяется) — фильтр. Адреса собирает `contactListHref(query, groupIds)` из `src/lib/group-filter.ts`; им пользуются поиск (`ContactSearch`, `router.replace`) и кнопки групп. Любая из них уже ведёт без номера страницы, то есть на первую.

После добавления контакта действие `createContact` делает `redirect("/?added=<id>")`. Главная ищет контакт в загруженном списке, подсвечивает строку, а `AddedContactNotice` прокручивает к ней, показывает уведомление и меняет адрес на `/` через `history.replaceState`.

Блоки «Скоро день рождения» и «Пора связаться» уже пропускаются, когда идёт поиск или фильтр (`filtered`): их запросы тогда не выполняются.

Ссылка «Все контакты» — серверный компонент `BackLink` (`src/components/back-link.tsx`) с `href="/"`. Она стоит в карточке (`src/app/contacts/[id]/page.tsx`), в форме нового контакта (`src/app/contacts/new/page.tsx`) и на странице «Группы» (`src/app/groups/page.tsx`). В форме «Изменить» `BackLink` ведёт в карточку, а не на список. Логотип «Context» в шапке (`src/components/site-header.tsx`) — ссылка на `/`.

## Goals / Non-Goals

**Goals:**

- Всё состояние листания — в адресе, страница остаётся серверной: обновление, «Назад» и другой браузер дают то же самое. Единственное, что помнит браузер, — адрес последнего открытого списка для ссылки «Все контакты» (решение 8)
- База отдаёт только нужный кусок списка, а не весь список
- Порядок на страницах — ровно тот же, что в общем списке сейчас (`nameOrder`, потом `id`), чтобы контакт не терялся и не повторялся между страницами

**Non-Goals:**

- Бесконечная прокрутка (подгрузка сама при прокрутке вниз) — только по кнопке
- Изменение размера страницы пользователем
- Листание блоков «Пора связаться», «Скоро день рождения» и страницы «Группы»
- Индексы в базе: при тысячах контактов у одного владельца сортировка тысячи строк быстрая

## Decisions

### 1. Адрес: `page` и `to`

Открытый кусок списка — это диапазон страниц с `page` по `to`. Первая страница без подгрузки — `/` без параметров. Одна страница N — `?page=N`. После «Загрузить ещё» — `?page=N&to=M`.

Разбор — чистая функция в новом `src/lib/paging.ts`: из `page`, `to` и числа найденных контактов она выдаёт `{ first, last, pageCount }`.

- `page`: только целое число больше нуля, иначе 1
- `page` больше последней страницы — последняя страница
- `to`: неверный или меньше `page` — равен `page`; больше последней страницы — последняя

Так поведение из спеки «Страница в адресе» проверяется unit-тестами без браузера.

`contactListHref` получает третий необязательный аргумент — диапазон страниц. Первая страница без подгрузки даёт адрес без `page` и `to`, поэтому все нынешние вызовы (поиск, кнопки групп) по-прежнему ведут на первую страницу. Так выполняется сценарий «Сменил запрос / Включил группу».

Отвергнуто:

- **Подгружать в браузере, адрес не трогать.** Подгруженное терялось бы после «Назад» и обновления, а владелец выбрал, чтобы оставалось
- **`?pages=3-4` одним параметром.** Читается не лучше, а разбирать сложнее

### 2. «Загрузить ещё» — ссылка, сервер перерисовывает весь диапазон

Кнопка — это `Link` на адрес с `to + 1` с `replace` и `scroll={false}`. Сервер заново рисует страницы с `first` по `to + 1`. React сохраняет уже показанные строки (ключ — `id`) и дописывает новые снизу. Прокрутка не сбрасывается, видимая часть не сдвигается.

`replace`, а не `push`: «Назад» в браузере ведёт туда, откуда пришли на список, а не отменяет подгрузку по одной странице. Из карточки «Назад» возвращает адрес с `to`, и Next.js достаёт эту страницу из кэша вместе с прокруткой.

Плюсы:

- Буквы не повторяются сами собой: `groupByLetter` получает один сплошной список
- Не бывает дублей и пропусков, если между нажатиями контакт добавили в другом браузере: весь диапазон читается одним запросом
- Ссылка работает и без JavaScript

Значок загрузки на кнопке — через `useLinkStatus` из `next/link` (есть в установленном Next.js 16.4.6) в маленьком клиентском компоненте внутри ссылки.

Отвергнуто:

- **Серверное действие, которое отдаёт следующие 100, и список в состоянии React.** Пришлось бы вручную склеивать буквы и синхронизировать адрес. Каждое нажатие при этом сэкономило бы лишь повторную пересылку уже показанных строк — при 1000 контактах это десятки килобайт

### 3. Запросы к базе

- `listContacts(ownerId, query, groupIds, { offset, limit })` — те же условия и порядок плюс `limit`/`offset`. `offset = (first - 1) * 100`, `limit = (last - first + 1) * 100`
- `countContacts(ownerId, query?, groupIds?)` — тот же фильтр, что у списка: число найденных для счётчика и для числа страниц. Вызов с одним `ownerId` по-прежнему даёт всех
- `contactListPosition(ownerId, contactId)` — номер контакта в общем списке без фильтров, с 1, или `null`, если контакта нет или он чужой. Считается через `row_number() over (order by <nameOrder>, id)` по контактам владельца, поэтому порядок гарантированно совпадает со списком. Страница — `ceil(position / 100)`

Порядок на главной:

1. Список групп пользователя
2. Если есть `added` — место контакта
3. Параллельно: число найденных, общее число, блоки (только если нет поиска и фильтра и `first === 1`)
4. Кусок списка

Получается два последовательных круга к базе вместо одного: число страниц нужно знать до того, как брать кусок, чтобы номер больше последнего открыл последнюю страницу.

Размер страницы — одна константа `CONTACTS_PAGE_SIZE = 100` в `src/lib/paging.ts`.

Отвергнуто:

- **`count(*) over ()` в самом запросе списка.** На странице за пределами списка строк нет, а значит нет и числа
- **Курсор («после такого-то имени») вместо `offset`.** Нужен прыжок на любую страницу по номеру, а курсор этого не умеет. При тысячах строк `offset` дешёвый

### 4. Номера в переключателе

Чистая функция `pageItems(first, last, pageCount, neighbors)` в `src/lib/paging.ts` отдаёт ряд элементов: номер или «…». В ряд всегда входят 1 и `pageCount`, все страницы с `first` по `last` и по `neighbors` соседних с каждой стороны. Разрыв ровно в одну страницу заполняется номером, а не «…» («1 2 3», а не «1 … 3»).

Переключатель рисует два ряда:

- для компьютера — `neighbors = 1`, класс `hidden sm:flex`: на 5-й из 10 «1 … 4 5 6 … 10»
- для телефона — `neighbors = 0`, класс `sm:hidden`: на 5-й «1 … 5 … 10», на 3-й «1 2 3 … 10», на 8-й «1 … 8 9 10»

Скрытый ряд (`display: none`) не попадает ни на экран, ни в дерево доступности (то, что читают программы экранного доступа и тесты), поэтому номера не дублируются. Каждый ряд разбит по своим правилам, и разрыв в одну страницу всегда закрыт номером.

Оба ряда переносятся на следующую строку (`flex-wrap`, по центру), если номера не помещаются в ширину. Так бывает на телефоне, когда подгружено много страниц: «1 2 3 4 5 … 10» со стрелками шире экрана.

Отвергнуто:

- **Один ряд, соседние номера скрыты классом на узком экране.** Соседний номер может одновременно закрывать разрыв у первой или последней страницы. Если его скрыть, разрыв остаётся без «…»: на 3-й странице получилось бы «1 3 … 10»
- **Открытый диапазон одной кнопкой («1–5»).** Это новый элемент, а перенос строки проще и не меняет правила

Подробности — в unit-тестах на функцию.

### 5. Компонент внизу списка

Новый `src/components/contact-list-pager.tsx` стоит внизу окна «контакты.exe», под списком, с верхней границей, как строка поиска сверху:

- Кнопка «Загрузить ещё» — `Button asChild` + `Link`, как «Добавить контакт», с клиентским значком загрузки внутри. Её нет, когда `last === pageCount`
- Ниже — `nav` с `aria-label="Страницы"`:
  - Стрелки — ссылки с `aria-label` «Предыдущая страница» и «Следующая страница»; неактивная стрелка — не ссылка, а элемент с `aria-disabled`
  - Номера — ссылки с `aria-label` «Страница N»: видимая цифра «2» иначе совпала бы с частью имён контактов в поиске по ссылкам
  - Открытые страницы выделены и помечены `aria-current="page"`
- Под переключателем — подпись «Показаны 101–200 из 1 000» мелким пиксельным шрифтом, как счётчик над списком. Текст собирает чистая функция `formatShownRange(from, to, total)` в `src/lib/format.ts`. Здесь `from = (first − 1) × 100 + 1`, `to = min(last × 100, найдено)`, `total` — число найденных. Если `from === to`, получается «Показан 101-й из 101». Числа — через `toLocaleString("ru-RU")`, как в `formatContactCount`
- Всё оформление — через токены и существующие варианты кнопки
- `prefetch={false}` у всех ссылок, как у строк списка: заранее загружать каждую страницу незачем
- Компонент не рисуется, если страница одна

### 6. Новый контакт

Если в адресе есть `added`, главная берёт `contactListPosition` и открывает страницу этого контакта, не глядя на `page`, `to`, `q` и `group`. После добавления их в адресе и нет. Подсветка и `AddedContactNotice` работают как раньше.

`AddedContactNotice` получает адрес страницы (`contactListHref("", [], { first: N, last: N })`) и ставит его через `replaceState` вместо `/`. После обновления остаётся та же страница, а уведомление не повторяется.

`contactListPosition` фильтрует по владельцу, поэтому номер чужого контакта даёт `null` и игнорируется так же, как несуществующий.

### 7. Блоки

Условие пропуска блоков становится таким: `filtered || first > 1`. Запросы блоков на второй и дальше страницах тоже не выполняются.

### 8. «Все контакты» — к списку, каким его оставили

Адрес последнего открытого списка хранится в `sessionStorage` (хранилище вкладки браузера: своё у каждой вкладки, очищается при её закрытии) под ключом `contactListHref`.

- **Запись.** Главная собирает на сервере адрес того, что сейчас показано: `contactListHref(query, groupIds, { first, last })`. Для `?added=` это уже адрес страницы нового контакта. Адрес передаётся в маленький клиентский компонент `RememberContactList`, который при каждой смене адреса записывает его в хранилище. Берём адрес с сервера, а не из `location`: в нём нет `added` и лишних параметров, и он уже приведён к правилам (номер больше последнего — последняя страница)
- **Чтение.** «Все контакты» в карточке, в форме нового контакта и на странице «Группы» становится клиентским компонентом `ContactListBackLink` поверх `BackLink`. Он читает адрес через `useSyncExternalStore`: на сервере и до загрузки скриптов — `/`, после — сохранённый адрес. Поэтому расхождения разметки сервера и браузера нет
- Принимается только адрес, который начинается с `/` и не с `//`. Всё остальное, а также пустое или недоступное хранилище (частный режим, запрет) — это `/`. Обращения к хранилищу обёрнуты в `try/catch`
- Форма «Изменить» и логотип «Context» не меняются. После «Изменить» → «Сохранить» открывается карточка, и её «Все контакты» читает тот же адрес из хранилища

Отвергнуто:

- **Параметр `from` в адресе каждой ссылки на карточку.** Он терялся бы после «Сохранить», новой заметки и «Пообщались»: действия ведут на `/contacts/<id>`. Его пришлось бы протаскивать через все формы и действия
- **Cookie.** Она общая для всех вкладок: две вкладки на разных страницах перебивали бы друг друга. Кроме того, писать её пришлось бы с сервера, а серверный компонент страницы cookie не пишет
- **`router.back()`.** Ведёт не туда, если карточку открыли по прямой ссылке или после «Изменить» → «Сохранить»: в истории тогда форма, а не список

## Risks / Trade-offs

- [Каждое «Загрузить ещё» пересылает весь открытый диапазон заново] → при 1000 контактах это не больше 1000 коротких строк; при заметно больших списках можно перейти на дописывание в браузере, адрес останется тем же
- [Контакт добавили или удалили в другом браузере между переходами по номерам] → соседние страницы сдвинутся на одну строку. Внутри открытого диапазона дублей нет, потому что он читается одним запросом. Для личной CRM приемлемо
- [Сравнение имён с правилом `ru-RU-x-icu` на каждый запрос] → при тысячах строк быстро. Индекс по выражению можно добавить позже, отдельной миграцией, без смены поведения
- [Возврат прокрутки после «Назад» зависит от кэша Next.js] → сценарий спеки проверяет то, что гарантировано адресом: те же 200 контактов. Прокрутку проверяем руками
- [Адрес `?page=99` не исправляется на `?page=3`] → открывается последняя страница, а стрелки и номера ведут на правильные адреса. Отдельный редирект не нужен
- [Первые миллисекунды после загрузки карточки «Все контакты» ещё ведёт на `/`: адрес подставляется, когда загрузились скрипты] → нажать так быстро почти невозможно, а худший случай — первая страница, как сейчас
- [Хранилище вкладки недоступно (частный режим, запрет сайтам хранить данные)] → «Все контакты» ведёт на первую страницу, как сейчас; ошибок нет
- [В хранилище лежит адрес с текстом поиска] → он не уходит на сервер сверх того, что уже есть в адресе страницы, и стирается при закрытии вкладки
- [Страницу «Группы» открыли из списка с фильтром, а группу там удалили] → номер удалённой группы в сохранённом адресе игнорируется по правилу «Группа из адреса не существует»: откроется список без этой группы

## Migration Plan

Миграции нет, схема базы не меняется. Выкатка обычная: merge → тест-стенд → проверка руками на копии данных прода → Deploy prod. Переключатель виден, только если у вошедшего больше 100 контактов (или больше 100 найдено); у владельца, если базу заполняли демо-данными, их 1000. Откат — галочкой «откат» в Deploy prod. Старые адреса без `page` продолжают работать как первая страница.
